# GUI Usability Assessment

狀態：歷史 GUI 易用性評估。P9a 已依本文件與 [../P9_GUI_ANALYZER_ASSESSMENT.md](../P9_GUI_ANALYZER_ASSESSMENT.md) 完成並驗收；現行開發主線請看 [../../ROADMAP.md](../../ROADMAP.md)。

評估日期：2026-06-27

本文件記錄從一般使用者角度檢視三個 GUI 介面的易用性與易讀性結果。此評估已納入 `ROADMAP.md` 的 P9 第一優先。

## 執行紀錄

- 2026-06-27：先行完成 `Link Checker` 進階設定欄位說明 tooltip。此項屬於 P9 第一優先的低風險前置小修，不改掃描語意、不改 report 契約。桌面支援 hover / focus，手機與觸控裝置可點擊問號顯示說明。

## 第一優先

P9 實作時，第一優先處理 GUI 可用性與可讀性基線，不先追加新的分析功能。

必修項目：

1. 修正 `External Link Analyzer` 手機版整頁水平溢出。
2. 簡化 `Link Checker` 初始狀態，避免一般使用者一開始看到大量技術指標與空的 `0` 統計。
3. 讓匯入型頁面採用更清楚的步驟式流程：選檔、可選規則、分析、匯出。
4. 手機版摘要區改為更緊湊，讓使用者更快看到結果清單。
5. 導覽名稱中文化或中英並列，例如「連結檢查」、「外連分析」、「報告分析」。

## 評估摘要

| 介面 | 易用性 | 易讀性 | 主要問題 |
| --- | --- | --- | --- |
| Link Checker | 中 | 中偏低 | 資訊密度高、狀態區太長、手機版要捲很多才看到結果 |
| External Link Analyzer | 中偏低 | 中偏低 | 匯入流程不夠直覺、手機版有整頁水平捲動 |
| Report Analyzer | 高 | 中高 | 最容易理解，但手機版摘要卡片太佔高度 |

## Link Checker

優點：

- 首要流程清楚：輸入 URL 後按「開始檢查」。
- 進階設定預設收合，方向正確。
- 掃描中有狀態、進度、事件紀錄與問題分類。

問題：

- 初始狀態顯示太多技術統計，例如目前請求、待爬佇列、Redirect、二次確認等。
- 一般使用者尚未開始掃描時，看到大量 `0` 會降低可讀性。
- 手機版頁面過長，結果區與事件紀錄需要捲很久才到。

建議：

- 初始狀態只顯示「尚未開始」與下一步提示。
- 掃描開始後再展開詳細技術指標。
- 結果分成「需要處理」、「可能誤判」、「技術診斷」三層。

## External Link Analyzer

優點：

- 頁面目標描述清楚。
- 指標、篩選、網域彙整、外連明細的資訊架構合理。

問題：

- 一般使用者不容易立即判斷要上傳 `external-links.csv` 還是 `report.json`。
- 「讀取外連清單」與「分析」兩步的狀態關係不夠直覺。
- 手機版有整頁水平溢出，尤其表格與寬欄位會造成底部水平 scrollbar。

建議：

- 改成明確步驟：選擇檔案、可選規則、分析結果。
- 手機版表格改用卡片式摘要，或確保水平捲動限制在表格容器內。
- 高風險分類與需檢視分類欄位可放入進階設定內，避免干擾基本流程。

## Report Analyzer

優點：

- 三個 GUI 中最容易上手。
- 使用者能直接理解「上傳 report.json」與摘要指標。
- 問題分類、來源頁排行、問題網域排行符合修復順序。

問題：

- 手機版摘要卡片一列一張，第一屏到第二屏多數都在看空指標。
- 空狀態仍顯示 disabled 的清除與匯出操作，對新手意義不大。

建議：

- 手機版摘要區改為更緊湊的 2 欄或列表式呈現。
- 未載入報告前隱藏清除與匯出，載入後再顯示。

## 驗收標準

P9 GUI 可用性第一優先完成時，至少應符合：

- 390px 寬手機 viewport 不出現整頁水平捲動。
- 三個 GUI 的第一屏都能明確回答「我下一步要做什麼」。
- 空狀態不顯示大量低價值技術統計。
- 匯入型頁面選檔後有清楚狀態與下一步提示。
- 桌面版保留技術資訊，但不壓過一般使用者的主要流程。
